## F4 — CERTIFICATION STABILITY as a foundational REQUIREMENT (text M0-ready; protocol pre-registered; NO run here — refuter PROMPT-34)
REQUIREMENT [CERT-STAB] (class PRACTICE, MEASURED on three instances at F2-B0): a certification verdict is a property of the TRIPLE (code tree hash, certificate recorder id + version, environment fingerprint). (i) Every Verdict PRINTS the triple. (ii) A design is QUOTABLE iff cert_worst <= 1/K_RICH under the pinned recorder AND its outcome class reproduces on re-run at the pinned (tree, env); the marginal band (1/K_RICH, 1] is quotable only if BOTH recorders (per-column, per-cell) agree on PASS. (iii) A certificate that does not reproduce is `fail=`-owned by an OPEN finding, never re-stamped. (iv) A change of any triple entry after an arm's run re-fires the protocol-drift rejector (R-TWIN-0).
PRE-REGISTERED CROSS-VERSION PROTOCOL (owner F2.ENGINE first act, with the X-O32 / X-LOCD re-forms): DESIGN SET = {S18 W* bell optimum (validation/s20_adaptive_design.json), the five S20 rejected marginal designs (validation/s22_rejected_designs.json), the S22 cert-limited base (s22_certlim_base.json), the X-CDKAT baseline}; RECORDERS = per-column and per-cell; BAND = outcome class must reproduce for every design; binary verdicts must reproduce for every design with cert_worst <= 1/K_RICH (any flip = FAIL); cert_worst must reproduce within the K_RICH factor; SEEDED REJECTORS = a design at cert_worst 0.9 refused as quotable; a doctored envfp refused; a doctored tree hash refused; PASS/FAIL = all-or-nothing per design set, printed with the triple. Falsifier of the requirement itself: a design with cert_worst <= 1/K_RICH whose binary verdict flips across the two recorders on the pinned (tree, env) — then 1/K_RICH is not the right margin and the requirement re-opens (owner F2.ENGINE).
