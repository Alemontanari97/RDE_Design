## The criterion (one rule, applied by a script)

A tracked file under validation/ is removed when it belongs to one of the three groups below AND none of the protections holds.

Groups:
1. the code, cases and run folders of the carriers RETIRED on 2026-10-09 (finding revalidation:carriers-retired-2026-10-09) and of the seven bell-line carriers declared failing before the revalidation and never re-run (X-AKNO, X-DEFTW, X-LOCD, X-LSG0, X-O32, X-HSYM, X-OBJD), retired here (finding revalidation:cleanup-2026-10-23);
2. the records of the optimiser campaigns run before the revalidation (owner, 2026-10-07: every optimiser result before it is not trusted; 2026-10-09: the old campaigns are repeated with the certified tool on the real outflow and the new records replace them);
3. brick-2 scripts of 2026-08 that no kept file imports and no carrier proves.

Protections (any one keeps the file):
- it is in the import closure of the kept code: the certified tool (a1_qntr, a1_plug_spline_opt, a1_ideal_march_jax, a1_plug_march, a1_twowall, a1_toc_variational_jax, a1_wavefront_replay), the revalidation harness, tests/, tools/, docs/ scripts, src/, examples/, the real-outflow tools, and the proof of every carrier that is not retired (same closure rule as the claims lint);
- a kept file names it (its whole relative path, or every component of it as a string): data the kept code reads;
- it is a .md document (session logs, advisories, raws are the record of what was done and stay).
